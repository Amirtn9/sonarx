# تطبیق قابلیت‌های SonarX با WizWiz

این سند بر اساس فهرست امکانات README فارسی پروژه مرجع WizWiz که توسط کاربر ارائه شده تهیه شده است. هدف، الگوبرداری از جریان‌های محصول و دسته‌بندی قابلیت‌هاست؛ کد PHP پروژه مرجع در SonarX کپی نشده است.

## قابلیت‌های موجود در SonarX

| حوزه | وضعیت فعلی |
|---|---|
| فروش و تحویل خودکار کانفیگ | موجود؛ PasarGuard محور اصلی |
| تمدید و افزایش حجم | موجود برای Adapterهای سازگار؛ با کنترل نتیجه |
| سرویس تست | موجود |
| اشتراک و لینک سرویس | موجود |
| QR سرویس | موجود در جریان کاربر |
| کیف پول و دفتر کل | موجود |
| شارژ کارت‌به‌کارت با تأیید مدیر | موجود |
| کد تخفیف و کد هدیه | موجود؛ انقضای تخفیف اکنون در اعتبارسنجی کنترل می‌شود |
| عضویت اجباری کانال | موجود |
| شماره تلفن تأییدشده | موجود |
| معرفی و کمیسیون | پایه موجود؛ تسویه نماینده کامل نیست |
| تیکت و پاسخ متنی | موجود؛ پیوست فایل/تصویر و SLA کامل نیست |
| مدیریت پلن، دسته و سرور | موجود؛ مدیریت همه فیلدهای پیشرفته پنل نیازمند توسعه است |
| ارسال پیام عمومی | مسیرهای پایه در ربات وجود دارد |
| قرعه‌کشی و گردونه شانس | قابلیت‌های پایه موجود |
| کنترل قابلیت‌ها | ماتریس Feature Flag موجود؛ قابلیت ناتمام قابل فعال‌سازی صوری نیست |

## تکمیل‌شده در این نسخه

- اصلاح PostgreSQL `RETURNING id` برای جدول‌هایی که کلید اصلی طبیعی دارند (`discount_codes`، `gift_codes` و `resellers`).
- ماسک‌کردن `DATABASE_URL` در خروجی CLI.
- ردکردن کد تخفیف منقضی یا دارای تاریخ نامعتبر.
- ثبت `server_id` و `remote_username` در سفارش‌های نامشخص.
- امکان تطبیق سفارش بررسی‌شده با اکانت موجود در پنل و تکمیل آن بدون ساخت مجدد اکانت.
- انتقال سفارش‌های قدیمی `processing` به صف بررسی توسط Watchdog.
- همگام‌سازی دوره‌ای مصرف، سقف حجم، تاریخ انقضا، وضعیت و لینک اشتراک از پنل.
- عدم گزارش موفقیت تغییر سرویس وقتی ثبت snapshot محلی شکست خورده است.
- کنترل خاموش‌بودن فروشگاه در مرحله نهایی خرید.
- جلوگیری از نمایش مرکز مدیریت در گروه تلگرام.
- اجرای خودکار Maintenance از طریق systemd timer.

## مواردی که هنوز کامل نیستند

این موارد در README مرجع WizWiz دیده می‌شوند، اما در SonarX فعلی Adapter یا جریان عملیاتی کامل ندارند:

| قابلیت | وضعیت | وابستگی لازم |
|---|---|---|
| x-uiهای Sanaei، Alireza، Vaxilu و Niduka | در دست توسعه | API و تست واقعی هر نسخه پنل |
| پنل Hiddify و WGDashboard | در دست توسعه | Adapter مستقل و تست Integration |
| درگاه Zarinpal، NextPay و NowPayments | پیاده‌سازی نشده | حساب پذیرنده، کلید API و Callback HTTPS |
| مدیریت چندپروتکل VLESS/VMess/Trojan و Reality/GRPC/WS | وابسته به API پنل | Adapter و مدل کانفیگ هر پنل |
| فروش انبوه و انبار کانفیگ | پیاده‌سازی کامل نشده | مدل موجودی، رزرو و تحویل اتمیک |
| تغییر UUID، تغییر پروتکل و تغییر لوکیشن | پیاده‌سازی کامل نشده | API عملیاتی پنل مقصد |
| انتقال موجودی بین کاربران | پیاده‌سازی کامل نشده | قواعد ضدتقلب و تراکنش انتقال دوطرفه |
| نمایندگی با کیف پول و تسویه | نیمه‌کامل | Ledger کمیسیون، درخواست تسویه و تأیید مدیر |
| لینک وب اختصاصی برای نمایش کانفیگ | پیاده‌سازی نشده | وب‌سرور، دامنه و سیاست دسترسی |
| پشتیبان‌گیری پنل VPN | پیاده‌سازی نشده | API/CLI رسمی هر پنل |
| اعلان‌های Cron سفارشی | پایه زمان‌بندی در حال توسعه | تنظیمات زمان‌بندی و صف ارسال |
| Mini App / پنل وب | پیاده‌سازی نشده | Frontend، API امن و احراز هویت |
| Smart Subscription و انتقال خودکار سرور | پیاده‌سازی نشده | الگوریتم انتخاب سرور، ظرفیت‌سنجی و سیاست انتقال |

## اصل مهم سازگاری

PasarGuard اولویت اصلی SonarX باقی می‌ماند. اضافه‌شدن پنل جدید فقط زمانی «پشتیبانی‌شده» اعلام می‌شود که عملیات Login، Create، Read، Renew/Quota (در صورت پشتیبانی پنل)، استخراج لینک و خطاهای Timeout در تست Integration واقعی تأیید شده باشند.
