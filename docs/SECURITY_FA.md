# چک‌لیست امنیت SonarX

- `.env` باید فقط برای مالک سرویس قابل خواندن باشد (ترجیحاً `0600`).
- `BOT_TOKEN`، `DATABASE_URL`، `FERNET_KEY` و رمز پنل هرگز در لاگ یا خروجی CLI چاپ نشوند.
- `FERNET_KEY` باید خارج از مخزن و در محل امن نگهداری شود؛ از دست‌رفتن آن به معنی عدم امکان رمزگشایی رمز پنل‌هاست.
- عملیات خصوصی حساب، سفارش، کیف پول و اشتراک فقط در گفتگوی خصوصی ربات انجام شود.
- نتیجه نامشخص عملیات پنل به صف بررسی برود؛ درخواست POST/PUT را کورکورانه تکرار نکنید.
- قبل از Migration دیتابیس، بکاپ PostgreSQL تهیه شود.
- پس از نصب/بروزرسانی، `sonarx doctor` و تست‌های پروژه اجرا شوند.
- نقش‌های `owner` و `admin` دسترسی کامل دارند؛ `operator` برای فروشگاه/پشتیبانی، `finance` برای مالی/بازبینی سفارش، `support` برای پشتیبانی، `marketing` برای رشد و `viewer` فقط برای داشبورد/گزارش محدود شده‌اند.
- شناسه‌های `ADMIN_IDS` مالک اصلی محسوب می‌شوند و از تمام مجوزها عبور می‌کنند. مدیران جانبی را با حداقل نقش لازم و از طریق `sonarx admin-add ID --role ROLE` اضافه کنید.
- مجوز Callbackها و مراحل ورود اطلاعات مدیریتی جداگانه بررسی می‌شود؛ تغییر نقش در میانه یک عملیات، مرحله متنی فاقد مجوز را لغو می‌کند.
